## Worker file-admission fix; focused validation complete — October 28, 2026 (UTC)

model/settings. Their source findings apply to released **82bae78 /0.26.103**:

- **Lease race:** release/sweep decide to unwatch before acquiring the project
  lock. A new lease can arrive while teardown waits, yet the queued teardown
  later removes the watcher without checking that lease again. Its occurrence
  during the recorded P3 transitions remains unproven.
- **Worker admission gap:** cancelling an assigned file task rejects its caller
  while native work correctly retains its worker. A batch can retry that same
  project/path on another worker before the old task finishes. The default
  180-second batch timeout versus 300-second hard worker deadline permits this
  interleaving. Neither occurrence nor CPU cost was measured on P3.

rejects promptly; blocked retries wait, while queries and unrelated files remain
eligible. Blocked entries do not drive demand scale-up or make existing-worker
queries yield. A task timeout still rejects/kills at its existing deadline, but
retains the file fence until child exit is observed. Exit handling reuses an
available idle worker, and a synchronous send failure continues dispatching the
next eligible retry. This does not add cross-process/file-alias deduplication,

### Batched MaxSim implemented locally — October 27, 2026
